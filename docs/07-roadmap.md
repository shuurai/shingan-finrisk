# 07 路线图

六个阶段，每个阶段有明确的交付物与推进条件。**推进条件是硬性的**：条件不满足就停在当前阶段，不因为"已经写了很多代码"而进入下一阶段。

| 阶段 | 目标 | 关键交付物 | 推进条件 |
| --- | --- | --- | --- |
| Stage 0 | 脚手架 | 仓库布局、CLI 命令面、configs 叠加、合成数据生成器、CPU demo、文档集 | 已完成（本仓库） |
| Stage 1 | 合成数据冒烟 | 全链路在合成数据上端到端跑通并出报告 | `shingan demo` 产出完整报告；leakage 断言在合成数据上通过 |
| Stage 2 | 5–10 家真实公司 POC | 真实 EDGAR + 新闻 + 价量的 processed 数据集与首份真实评测 | 数据接入成功；标签可核对；headline 指标与置信区间产出一份报告 |
| Stage 3 | 融合 + 三路消融 | fused 相对 structured-only 的增量证据（含 placebo 对照） | 融合增益的置信区间不跨零，且 placebo 对照显示指标下降 |
| Stage 4 | 全 S&P 500 / 20 年 | 可复现的大规模数据集与多 regime 评测 | 点内成分股名单（PIT membership）接入；walk-forward 稳定性通过 |
| Stage 5 | Hugging Face 发布 | 模型卡、数据集卡、benchmark、Zenodo DOI | 前四阶段的门槛全部达成且如实披露 |

## Stage 1 — 合成数据冒烟

**目标**：证明流水线的连通性与正确性，而不是性能。

**交付物**

1. `shingan demo` 的完整 markdown 报告（`runs/<ts>-demo/report.md`），包含指标表、校准图数据、分位回测表、walk-forward 折表。
2. `leakage.py` 全部断言在合成数据上通过，且**能对注入的泄漏样本抛错**（需要有反例测试：故意把一个 `event_date` 派生列放进 X，断言必须失败）。
3. 三个标签的合成正样本率与生成器配置一致（抽样检查）。
4. purge/embargo 的实际区间与[评测](05-evaluation.md)第 3.3 节的算例一致。

**推进条件**

| 条件 | 判据 |
| --- | --- |
| 端到端可跑 | `shingan demo` 在无网络、无 GPU 的机器上成功产出报告 |
| 泄漏防护有效 | 注入式反例测试全部触发断言失败 |
| 切分正确 | 报告打印的实际区间与文档算例一致（误差 0 天） |
| 融合增益方向正确 | fused 在合成数据上的 PR-AUC 高于 structured-only。这是**构造保真的检查**，不是发现（见[数据](02-data.md)第 3.2 节） |

**风险**：无。这一阶段失败意味着实现 bug，不是项目失败。

## Stage 2 — 5–10 家真实公司 POC

**目标**：第一次接触真实数据，检验"数据能不能拿到、标签能不能核对、指标能不能算"。

**公司集合建议**：`JPM`、`GS`、`GE`、`CAT`，覆盖金融与工业两个板块，加上若干家构成混合样本，并**至少包含一家已知的困境/退市公司**（用于保证正样本存在）。具体名单在 `configs/data/stage2.yaml` 中固定。

**时间跨度**：2015–2024。

**为什么是这几家**：

| 公司 | 板块 | 入选理由 |
| --- | --- | --- |
| `JPM` | 金融 | 大型银行，财务比率与信用风险标签最相关，披露质量高，文本噪声低 |
| `GS` | 金融 | 与 JPM 同业但业务结构不同，用于检验模型是否只学到"银行股"的共同模式 |
| `GE` | 工业 | 经历过重大业务重组与信用评级压力，是少见的"大市值但确实发生过风险事件"的样本 |
| `CAT` | 工业 | 强周期工业，量价特征与财务比率的关系与金融股形成对照 |
| 至少一家已知困境/退市公司 | — | 没有正样本就没有评测。已知困境公司是保证样本里存在正例的最直接手段 |

**交付物**

1. 真实数据的 `data/processed/` 面板 + `data_version`。
2. 一份标注复核记录：至少抽查 50 条（或全部正样本），不一致率写入数据集卡。
3. 首份**真实数据**评测报告，包含 structured-only / text-only / fused 三路与无模型基线，以及全部置信区间。
4. 数据获取与清洗的实际损耗统计：EDGAR 请求成功率、新闻覆盖度、价格缺口率、各标签的 `label_mask` 为 `false` 的比例。

**推进条件**

| 条件 | 判据 |
| --- | --- |
| 数据接入可用 | 三家源的适配器在真实端点上跑通，成功率与损耗被量化记录 |
| 标签可核对 | 每个正样本都能追到 `source_of_record`（见[标注](03-labeling.md)第 6 节） |
| 无穿越 | `leakage.py` 断言在真实数据上通过；人工复核 10 条随机样本的特征时间戳 |
| headline 产出一份 | 即使指标不达门槛，只要能给出带置信区间的结果即算通过本条件 |
| 诚实披露 | 报告中明确标注哪些部分是代理事件、哪些源未接入 |

**风险（本阶段风险最集中）**

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **评级历史不可得** | `default_risk` 无法按原定义标注，只能用代理事件（8-K Item 2.04、退市通知） | 显式降级并在数据集卡声明。这是**最可能迫使定义修改**的风险 |
| **正样本太少** | `fraud_risk` 在 5–10 家公司的 2 年窗口内可能为 0 | 把 Stage 2 定位为"数据管线验证"而不是"性能验证"；正样本数 < 20 时按[评测](05-evaluation.md)第 10 节的 F8 处理 |
| **EDGAR 全文解析质量** | HTML 清洗不干净，Item 切段错位 | 人工抽查 20 份 filing 的切段结果；把 Item 1A 与 Item 7 的抽取正确率作为一项交付指标 |
| **新闻时间戳质量** | FNSPID 的发布时间戳若为抓取时间而非发布时间，会造成穿越 | 抽查 50 条，核对是否有发布时间晚于 `fetched_at` 的异常 |
| **`fraud_risk` 的 valid 窗口只有约 22 个月** | 校准器只能走 Platt，校准质量不可靠 | 已预期。报告中标注校准器的样本数与正样本数 |
| **公司数量太少导致横截面回测无意义** | 5–10 家公司无法做有意义的五分位 | Stage 2 不做分位回测（把 `eval/backtest.py` 的输出标记为不适用），只报告 IC 与分类指标 |

**必须在 Stage 2 结束时回答的问题**：如果正样本数不足以支撑任何统计结论，是扩大公司集合（提前进入 Stage 4 的一部分），还是修改标签定义（降 horizon 或放宽阈值）？这个决定需要记录成一份新的 ADR。

## Stage 3 — 融合与三路消融

**目标**：回答项目的中心问题——文本轨在结构化信号之外是否提供可度量的增量。

**交付物**

1. 完整的对比矩阵：`random` / `buy_and_hold` / `equal_weight` / `structured_only` / `text_only_tfidf` / `text_only_zero_shot` / `text_only_lora` / `fused_stacker` / `fused_rank_avg`，每格含指标 + 置信区间。
2. 消融矩阵：去掉文本、去掉财报、去掉新闻、去掉技术指标、去掉财务比率（见[评测](05-evaluation.md)第 5.2 节）。
3. **placebo 对照**：打乱文本后的指标。这是本阶段的必做项。
4. 融合层权重的报告（logistic stacker 的系数或 rank-average 的权重），以及它在各折之间的稳定性。
5. 一份明确写出的结论：文本轨有增量 / 无增量 / 证据不足。三种结论都是可接受的结果，"证据不足"必须被允许。

**推进条件**

| 条件 | 判据 |
| --- | --- |
| 三路对比完整 | 九条路径全部有带置信区间的结果 |
| 融合增益显著 | fused 的 PR-AUC 高于 structured-only，且 bootstrap 区间不跨零 |
| placebo 有效 | 打乱文本后指标显著下降。**若不下降，不应进入 Stage 4，而应回头排查泄漏与捷径** |
| 统计口径正确 | IC 使用连续前瞻量；分位回测按横截面逐日排序；所有区间来自时间块 bootstrap |
| 结论允许为负 | 报告必须能为"文本无增量"这一结论留出位置，不得只呈现正面结果 |

**风险**

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 融合增益不显著 | 项目核心论点被证伪 | 这是**有效结论**，不是失败。按[评测](05-evaluation.md)第 10 节的 F1/F2/F3 逐条排查后如实报告 |
| placebo 未通过 | 说明存在未发现的泄漏或捷径 | 优先级最高，必须先解决才能继续 |
| 小样本下的置信区间过宽 | 无法判定 | 扩大样本（进入 Stage 4）或缩减结论的强度 |
| LLM 分数与结构化分数高度相关 | 融合没有空间 | 这本身是有价值的发现（文本在复述数字），应报告并分析 |

## Stage 4 — 扩展到全 S&P 500 / 20 年

**目标**：把结论从 5–10 家公司推广到横截面，覆盖多个市场 regime。

**交付物**

1. 全 S&P 500、约 20 年跨度的 processed 数据集（含 `data_version` 与完整的数据字典）。
2. **点内成分股名单（point-in-time membership）**。这是本阶段的阻塞项：只用当前成分股会引入系统性幸存者偏差，直接压低正样本率并高估模型表现（见[数据](02-data.md)第 4.4 节）。
3. 多 regime 评测，含[压力测试](05-evaluation.md)的 2008 / 2020 / 2022 三个场景。注意：**2008 场景要求数据回溯到 2005 年之前**。若数据从 2005 年开始，则该场景不可用，必须如实标注为不可用而不是省略。
4. 跨行业泛化评测（按 sector 分组）。
5. 端到端重跑的耗时与成本记录（数据抓取、特征构建、训练、评测）。

**推进条件**

| 条件 | 判据 |
| --- | --- |
| PIT 成分股接入 | 历史成分股名单可用，且报告了纳入/剔除公司的数量 |
| 正样本统计充分 | 每个标签的正样本数足以做分层评估（经验下限：>= 100，低于此值所有结论都标注为不确定） |
| 稳定性通过 | walk-forward 各折的置信区间稳定地高于随机，无单调下降趋势 |
| 漂移可监控 | PSI/CSI 在可解释范围内，或漂移被定位到具体数据源变化 |
| 校准可分年验证 | 逐年的 ECE 都被报告 |
| 成本可承受 | 全量抓取与训练在单机（一台 RTX 5090）上可完成，总耗时在可接受范围 |

**风险**

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| **幸存者偏差** | 结论系统性偏乐观 | PIT 名单是硬性前置条件，不满足则本阶段不通过 |
| EDGAR 抓取成本 | 全量 10-K/10-Q/8-K 的抓取时间与磁盘占用 | 先做增量抓取与压缩存储；把原始响应与清洗后文本分开存储 |
| 20 年的数据一致性 | 早期年份的 XBRL 覆盖差、披露格式与词典不同 | 分段评测（按十年分组），不假设跨期可比 |
| 计算成本 | 全量文本轨训练时间 | 14B QLoRA 在 32 GB 上可行，但全量样本需要多轮训练。记录实际耗时并据此判断是否需要 30B-A3B 或分布式 |
| 标签定义在新公司上不适用 | 小市值/高波动公司的 `tail_risk` 基率远高于大市值 | 按市值分组报告基率，不做全局阈值调整 |

## Stage 5 — Hugging Face 发布

**目标**：把可复现的 artifact 公开，并让所有限制都被明确写在最显眼的位置。

**交付物**

| artifact | 名称 | 内容 |
| --- | --- | --- |
| 模型 | `shuurai/shingan-qwen3-14b-finrisk` | QLoRA adapter + merged 权重（择一，卡中说明） |
| 数据集 | `shuurai/shingan-finrisk-labels` | 标签 + 派生特征，**不含**原始新闻正文（见[数据](02-data.md)第 6 节） |
| Benchmark | `shuurai/shingan-bench` | 评测集与基线结果，含全部置信区间 |
| 代码 | GitHub `shuurai/shingan` | Apache-2.0 |
| 文档 | 本文档集 | 含[模型卡](../templates/model_card.md)、[数据集卡](../templates/dataset_card.md) |
| 存档 | Zenodo DOI | 与 GitHub release tag 绑定，保证可引用 |

**推进条件**

| 条件 | 判据 |
| --- | --- |
| 前四阶段门槛达成 | 每一项都被如实标注为达成或未达成 |
| 模型卡完整 | 含 Intended Use（明确 research/education only，非投资建议、非交易系统、非尽调替代）、Out-of-scope Use、Limitations 与 Risks、Environmental Impact |
| 数据集卡完整 | 含 provenance、逐源许可与署名、as-of 纪律、已知偏差（幸存者偏差、重述前视、仅英文、仅美上市）、个人信息说明 |
| 再分发合规 | 未随发布的 artifact 分发任何受限制的原始数据（新闻正文、价格面板、商业评级数据） |
| 结果可复现 | 从 `data_version` + 种子 + 环境指纹能重跑出同一份报告（统计意义上） |
| 无过度声明 | 全仓库不存在任何"已达成 X 指标"的表述，除非该指标有对应的可复现报告 |

**风险**

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 结果被误读为投资建议 | 合规与声誉风险 | 模型卡与 README 的最前部写明限制；输出契约的 JSON 中保留 `calibrated` 字段以防被当作概率滥用 |
| 再分发侵权 | 法律风险 | 发布前逐源核对再分发条款；不含原始正文 |
| 数字被脱离上下文引用 | 误导 | 所有指标必须与切分定义、置信区间、正样本数一起呈现，不发布孤立的数字 |
| 项目被当作"已验证的模型" | 过度自信 | 在模型卡与数据集卡的 Limitations 段并列写明"合成数据只验证流水线"与"真实数据结论的适用范围" |

## 全局风险与前置依赖

| 风险 | 影响的阶段 | 说明 |
| --- | --- | --- |
| 评级历史不可得 | 2–5 | 迫使 `default_risk` 的定义降级为代理事件。这是**最可能改变项目定义**的外部约束 |
| 商业金融数据无许可 | 2–5 | 相关特征与标签只能替换为公开代理，模型上限因此受限 |
| 稀有事件的统计下限 | 2–5 | 正样本不足时任何指标都不可判定。这是任务本身的属性，无法通过工程手段消除 |
| 单机算力 | 4–5 | 全量数据下的训练轮次受 32 GB 显存与单卡吞吐限制 |
| 平台风险（Windows/Blackwell） | 1–5 | 已在 [ADR-0002](adr/0002-training-stack-windows.md) 中处理，并有 WSL2 回退路径 |
