# ADR-0003: 采用双轨架构，拒绝单一 LoRA

- 状态：Accepted
- 日期：2026-09-21
- 决策者：Shane（`shuurai`）

## Context

项目的原始设想是：把 20 年 S&P 500 公司的年报全文、20 年新闻、以及交易信号序列化成一个统一的大文本输入，用**一个 LoRA** 端到端预测风险。这个设想被否定了，但在架构层面一直没有形成正式记录，因此在此确立。

相关的技术事实：

1. 结构化信号（财务比率、量价/微观结构特征）构成一个宽而浅的数值面板：列间高度相关、量纲各异、普遍缺失、样本量以数万计。gradient-boosted trees 在这类数据上稳定、可校准、可归因。
2. 非结构化文本（10-K/10-Q/8-K 摘录、新闻）的信号以措辞、篇幅变化、语义密度等形式出现，其中的关键信息通常**不会**被编码进任何数值字段。
3. 项目的核心命题是"文本轨在结构化信号之外提供可度量的增量"。这是一个需要归因的问题。
4. 三个标签的 horizon 差异达一个数量级（365 / 730 日历日、30 交易日），合并成单一分类任务会迫使最长 horizon 主导梯度。

## Decision

采用**双轨 + 融合**架构：

- **Track A（结构化）**：GBDT（LightGBM/XGBoost）作用于财务比率 + 技术/微观结构 + 文本计数量特征；在 train 上拟合，在 **valid fold 上**用 isotonic 或 Platt 显式校准。
- **Track B（文本）**：QLoRA 指令微调 `Qwen/Qwen3-14B`，输入为 `as_of` 前已公开的披露文本与新闻，输出证据化的 JSON（`label` / `severity` / `score` / `horizon_days` / `reasons[]` / `evidence[]`）。另设一条**非 LLM** 的 text-only 基线（TF-IDF + 线性模型）。
- **Track C（融合）**：logistic stacker 或 rank-average，输入仅为两条轨的分数；**只在 valid fold 上拟合**，在 test 上只做一次前向计算。
- **强制消融**：任何性能声明必须同时给出 `structured_only`、`text_only_lora`、`fused` 三路结果，外加 `text_only_tfidf`、`text_only_zero_shot` 与无模型基线；并包含打乱文本的 placebo 对照。

被拒绝的是"单一 LoRA 吞下全部输入"这一架构，**不是 LoRA 本身**：LoRA 保留，但只作用于文本轨。

## Consequences

正面：

- "文本是否带来增量"成为一个可测量的实验问题（`fused` 相对 `structured_only` 的 PR-AUC 差值），这是本项目最核心的科学问题。
- 两条轨各自可以被单独调试、单独校准、单独归因；失败时可以定位到具体一侧。
- 三个标签在同一份特征上由三个独立的二分类头分别监督，不需要在文本里塞入"距离事件还有多久"这类会泄漏的信息。
- TF-IDF 基线的存在使"LLM 是否必要"可被检验，避免默认采用最贵的方案。

代价与约束：

- **两个 artifact 而非一个**：模型发布时需要同时给出结构化轨的模型文件与 LoRA adapter，模型卡需要说明两者的关系与融合方式。
- **多出一个融合步骤**：融合层的参数需要自己的拟合区间（valid）与报告字段；融合层的失效会成为额外的故障点。
- **消融是强制的**：每个阶段的报告都必须包含三路对比与 placebo，报告工作量显著增加，且不能只报告最好的一路。
- **校准逻辑分处两地**：Track A 的校准器与 Track C 的融合层都必须遵守"只在 valid 上拟合"，实现上需要统一约束（由报告元数据强制校验），否则容易出现某一处用了 test。
- **不能通过"增大模型"来回避问题**：切换到 30B-A3B 或更大底座不会替代架构决策；若 `text_only_tfidf` 已追平 LoRA，更大的模型不是答案。
