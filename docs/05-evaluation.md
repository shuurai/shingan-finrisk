# 05 评测

评测框架的目标不是给出一个好看的数字，而是让"文本轨是否带来增量"成为一个可以被证伪的实验问题。本文定义指标与目标门槛、切分设计（含 purge 与 embargo）、六项会导致错误结论的实现陷阱、压力测试、基线与消融、漂移监控、可解释性、POC 验收门槛，以及明确写出的证伪条件。

**门槛的读法**：文中所有指标数值都是**目标值（target/gate）**，不是达成值。

真实数据上的评测**已经跑过**（`artifacts/reports/`，34 家公司 / 2,221 行面板 / 492 行 test）。但它不改变上面那句话：那次运行的门禁结果是 `headline_auc` 未达、融合增益区间跨零、`brier_beats_base_rate` 未达，而且 test 块只有 **5 个正样本**——按本文第 10 节的 F8，这不构成性能声明。文本轨的增量至今**未知**，理由见 [09 LoRA 评测](09-lora-evaluation.md)。

## 1. 评测原则

| 原则 | 含义 |
| --- | --- |
| 排序优先于分类 | 风险模型的核心用途是把有限的复核注意力排到最前面，因此 AUC/KS/PR-AUC/IC 优先于阈值化的 accuracy/F1 |
| 校准是硬要求 | 输出必须是概率，才能进入任何风险流程。ECE 与 Brier 与排序指标同等重要 |
| 切分必须按时间 | 面板数据的样本不独立。任何随机切分都是错的 |
| 边界必须 purge + embargo | horizon 长达 730 天时，训练样本的标签窗口会覆盖测试区间。见第 3 节 |
| 评估集不降采样 | 降采样只用于训练；评估必须反映真实基率，否则 ECE 与 PR-AUC 都被扭曲 |
| headline 只用一次 | 测试集只跑一次，结果只报告一次。反复调参会造成隐性过拟合 |
| 没有三路对比就没有结论 | 任何性能声明必须同时给出 structured-only、text-only、fused 与无模型基线 |
| 有对照才有归因 | 文本轨必须有 placebo 对照（打乱文本），否则无法排除模型在用长度/公司身份等捷径 |

## 2. 指标与目标门槛

### 2.1 排序与区分

| 指标 | 定义 | 目标门槛 | 备注 |
| --- | --- | --- | --- |
| AUC-ROC | 区分正负样本的整体能力 | **> 0.75**（headline gate） | 对阈值不敏感，金融模型常用首选 |
| KS | 正负样本分数累计分布的最大差距 | **> 0.3**（headline gate） | 达到 0.3 通常认为有区分力 |
| PR-AUC | precision-recall 曲线下面积 | **fused 必须显著高于 structured-only** | 稀有正样本下的首选指标，也是本项目的核心判据 |
| PR-AUC 基线对照 | PR-AUC 相对随机基线的比值 | 显著高于随机（随机基线 = 正样本率） | 单看 PR-AUC 绝对值在极低基率时没有意义 |
| F-beta（β>1） | 加权召回率的 F 分数 | β 取值由业务代价决定，POC 默认 β=2 | 风控中"漏杀"代价高于"错杀"；必须在报告中写明 β 与对应阈值 |
| CAP / AR | 累积准确率曲线与准确率比 | Top 5% 组的正样本捕获率显著高于基率 | 对应"复核前 5%"的实际工作流 |
| 风险分层单调性 | 按分数分 10 组的实际正样本率是否单调递增 | 单调，或仅末端轻微反转 | 末端反转在稀有事件下常见，需报告而非掩盖 |

### 2.2 排序稳定性与经济意义

| 指标 | 定义 | 目标门槛 | 备注 |
| --- | --- | --- | --- |
| IC（Spearman） | 预测分数与**连续前瞻量**的秩相关 | **> 0.05** | 有经济意义的经验下界；前瞻量的选择见陷阱 3 |
| ICIR | IC 均值 / IC 标准差 | **> 0.5** | 衡量信号稳定性 |
| IC 的 t 统计量 | 用 Newey-West 调整自相关后的 t 值 | 显著异于 0 | IC 序列有自相关，必须调整 |
| 横截面分位回测 | 逐日按分数分位，再对每日分位收益取均值 | 高风险分位收益显著低于低风险分位 | 做法见陷阱 2 |
| 多空组合 Sharpe | 分位多空价差的年化夏普 | **> 1.0**（目标，未验证） | 在稀有事件与小样本下很可能达不到 |
| 最大回撤 / Calmar | 组合回撤与回撤调整收益 | 与基准对比，不设固定门槛 | — |

### 2.3 校准

| 指标 | 定义 | 目标门槛 |
| --- | --- | --- |
| ECE | 分桶后的预测概率与真实频率之差的加权平均 | **< 0.05** |
| Reliability Diagram | 分桶预测概率 vs 桶内真实频率 | 贴近对角线 |
| Brier Score | 概率预测的平方误差 | 必须优于"常数基率"基线的 Brier |
| 分层校准 | 按年份、按行业分别看 ECE | 不出现系统性单一方向偏差 |
| 尾部校准 | 最高分位桶内的校准误差 | 单独报告。风控关心的是高分区，整体 ECE 好不代表高分区好 |

校准的强制性约束：校准器（isotonic 或 Platt）与融合层的参数都**只在 valid fold 上拟合**，test fold 只做 transform。见第 4 节陷阱 6。

### 2.4 稳定性与漂移

| 指标 | 定义 | 目标门槛 |
| --- | --- | --- |
| PSI | 特征分布随时间的变化 | **< 0.25** |
| CSI | 分数分布随时间的变化 | **< 0.25** |
| 滚动窗口指标波动 | 各滚动折的 AUC/KS/IC 的离散度 | 见下方诚实说明 |
| 跨行业泛化 | 按 sector 分组分别评测 | 不出现某行业完全失效 |

**诚实说明**：一条常被引用的门槛是"滚动窗口指标波动 < 10%"。在正样本率个位数、某些折的正样本数可能是个位数的情形下，这个门槛在统计上不可达——单折 AUC 的抽样标准差本身就可能超过 10%。本项目把该门槛降级为**观察项**：报告各折指标的分布与置信区间，用 bootstrap 给出区间宽度，而不是用一个固定百分比判定通过。真正有意义的判据是"指标的置信区间是否稳定地高于随机"，以及"是否存在单调下降趋势"。

## 3. 切分设计：purged walk-forward + embargo

- 实现：`src/shingan/eval/splits.py`
- 配置：`configs/eval/*.yaml` 的 `split` 段，键包括 `purge_days`、`embargo_days`、`test_block_years`、`step_years`

### 3.1 为什么需要 purge 与 embargo

面板数据里，一个 `(ticker, as_of)` 样本的标签由 `as_of` **之后** `H` 天内的信息决定。这意味着样本的"信息占用区间"是 `[as_of, as_of + H]`，而不是 `as_of` 这一点。

如果训练集以 2018-12-31 结束、测试集从 2019-01-01 开始，那么在共享同一批公司的情况下：

- 训练集中 `as_of = 2018-06-01` 的样本，其 `default_risk` 标签由 2018-06-01 到 2019-06-01 之间的事件决定。**这段区间与测试集的前半年重叠**。
- 更极端地，`as_of = 2018-12-31` 的样本，其 `fraud_risk` 标签由截至 2020-12-31 的信息决定，**几乎完全落在测试区内**。

后果是：模型在训练时已经"看过"测试期发生的事件的后果，测试指标会被系统性高估。这就是 leakage，而且它不会表现为任何显式的错误——分数只是偏高。

两个防护手段：

- **Purging（净化）**：把训练集中所有"信息占用区间"与后续折（valid/test）区间重叠的样本删除。
- **Embargo（隔离期）**：在 purge 之外，额外删除紧邻折边界的一段样本。它针对的是序列相关——即使标签窗口不重叠，边界两侧的特征（如价量、新闻情绪、市场 regime）仍然高度相关，边界附近样本的独立性不足。Embargo 的长度是一个先验选择（本项目默认 30 个交易日），不是从数据里估出来的。

### 3.2 参数化

```
purge_days    = max(horizon_days of evaluated labels)   # default: 730
embargo_days  = 30 个交易日（≈ 42 日历日）
margin_days   = purge_days + embargo_days

train 中保留 as_of <= valid_start  - margin_days
valid 中保留 as_of <= test_start   - margin_days
test  中保留 as_of <= data_end     - horizon_days(该标签)
```

`purge_days` 取三个标签 horizon 的最大值（730），是为了让同一套折能同时评测三个标签。代价很大，这一点在 3.4 节量化。

### 3.3 一个完整算例

以 `default_risk`（H = 365 日历日）为例，`margin_days = 365 + 42 = 407`。

名义边界：

| 折 | 名义区间 |
| --- | --- |
| train | 2010-01-01 .. 2017-12-31 |
| valid | 2018-01-01 .. 2020-12-31 |
| test | 2021-01-01 .. 2024-12-31 |

逐步应用规则：

1. **train**：`valid_start = 2018-01-01`。丢弃 `as_of >= 2018-01-01 - 407 天 = 2016-11-20` 的样本 → train 有效区间 `2010-01-01 .. 2016-11-19`。丢掉的是 `2016-11-20 .. 2017-12-31`（约 13.4 个月）。
2. **valid**：`test_start = 2021-01-01`。丢弃 `as_of >= 2021-01-01 - 407 天 = 2019-11-20` 的样本 → valid 有效区间 `2018-01-01 .. 2019-11-19`。丢掉的是 `2019-11-20 .. 2020-12-31`（约 13.4 个月）。
3. **test**：右端受标签可观测性截断。`data_end = 2024-12-31`，需要 `as_of + 365 <= 2024-12-31` → `as_of <= 2023-12-31` → test 有效区间 `2021-01-01 .. 2023-12-31`。最后一年（2024）不能作为 `default_risk` 的测试行，因为它的标签窗口尚未走完。

这一步容易被完全忽略：**样本的右端必须按 horizon 截断，否则末端样本会被当作负样本，凭空制造假阴性。** 被截断的行标记为 `label_mask = false`，不参与训练与评估。

**关键结论（一个反直觉但重要的设计约束）**：由于 `margin_days` 达到 407 天（`fraud_risk` 更是 772 天），**紧邻测试集之前的 1 年窗口不可能构成一个有效的 valid fold**——它会被 purge 全部吃掉。因此 valid 折必须与 test 折之间保持至少 `margin_days` 的距离，或者 fold 块长必须大于 `margin_days`。本项目采用后者：`test_block_years` 默认 2，且 valid 折与 test 折之间不重叠、由 purge 自动形成间隔。

### 3.4 各标签的有效区间

`eval/splits.py` 按公式直接计算日期，下表给出同一名义切分下三个标签的落地结果（`embargo_days = 30 交易日 ≈ 42 日历日`）。表中日期为按规则计算的近似值，精确值以 `splits.py` 输出为准（脚本在报告页首打印实际区间）。

| 标签 | H | margin | train 有效区间 | valid 有效区间 | test 有效区间 |
| --- | --- | --- | --- | --- | --- |
| `default_risk` | 365 | 407 | 2010-01-01 .. 约 2016-11-19 | 2018-01-01 .. 约 2019-11-19 | 2021-01-01 .. 2023-12-31 |
| `fraud_risk` | 730 | 772 | 2010-01-01 .. 约 2015-11-20 | 2018-01-01 .. 约 2019-11-20 | 2021-01-01 .. 约 2022-12-31 |
| `tail_risk` | 30 交易日（≈42 日历日） | 84 | 2010-01-01 .. 约 2017-10-08 | 2018-01-01 .. 约 2020-10-08 | 2021-01-01 .. 2024-11-19 |

这张表本身就是对项目可行性的一个诚实交代：

- `fraud_risk` 在 2010–2024 的数据跨度下，valid 有效区间约 22 个月（`2018-01-01` 到约 `2019-11-20`，尾部 13 个月被 purge 吃掉），test 有效区间只有 2 年。若正样本率是低个位数百分比，valid 的正样本数可能只有个位数到十几个——校准器只能走 Platt，且校准质量本身不可靠。`fraud_risk` 是三个标签中数据效率最差的一个。
- `tail_risk` 的窗口损失最小，因为它的 horizon 最短。三个标签放在同一套折里评测时，`tail_risk` 的数据效率最高。
- **一个可选的替代方案**：为每个标签单独跑一套切分（`purge_days` 按该标签的 horizon 设置）。这样 `tail_risk` 能用几乎全部数据，`default_risk` 的损失也减半。代价是三套切分意味着三份报告，跨标签比较时的区间不一致。本项目默认使用统一折（便于对比），把 per-label 切分作为可选配置 `split.per_label: true`，并在报告中显式标注使用了哪一种。

### 3.5 Walk-forward 折

静态切分给出 headline 结果，walk-forward 给出稳定性。设计：expanding window，`test_block_years = 2`，`step_years = 2`，每折内部先切出 valid。

以下为 `default_risk` 的折表（`margin = 407` 天）：

| 折 | train 名义 | train 有效 | valid 名义（部分被 purge） | valid 有效 | test |
| --- | --- | --- | --- | --- | --- |
| W1 | 2010-01-01 .. 2014-12-31 | 2010-01-01 .. 约 2013-11-19 | 2015-01-01 .. 2016-12-31 | 2015-01-01 .. 约 2015-11-19 | 2017-01-01 .. 2018-12-31 |
| W2 | 2010-01-01 .. 2016-12-31 | 2010-01-01 .. 约 2015-11-19 | 2017-01-01 .. 2018-12-31 | 2017-01-01 .. 约 2017-11-19 | 2019-01-01 .. 2020-12-31 |
| W3 | 2010-01-01 .. 2018-12-31 | 2010-01-01 .. 约 2017-11-19 | 2019-01-01 .. 2020-12-31 | 2019-01-01 .. 约 2019-11-19 | 2021-01-01 .. 2022-12-31 |

每折产出独立的指标向量（AUC / KS / PR-AUC / IC / ECE）。报告呈现：

1. 各折指标值 + bootstrap 置信区间。
2. 指标的均值与离散度。
3. 是否存在单调趋势（用 Theil-Sen 或简单的首末折对比，不做正式的断点检验——样本量不够）。
4. **每个折内部重新拟合校准器与融合层**。跨折复用校准器是泄漏。

### 3.6 静态切分与 walk-forward 的关系

| 用途 | 按此使用 |
| --- | --- |
| Headline 数字 | 静态切分，只在 test 上跑一次 |
| 稳定性 | walk-forward，全部折都报告 |
| 调参 | 只在 valid 上，且调参记录必须留档 |
| 校准器与融合层拟合 | 静态切分用其 valid；walk-forward 每折用自己的 valid |

只报告一个静态切分是不够的：单一测试区间可能恰好落在一个特殊的市场 regime 中（例如 2020 年的极端波动），使得结论不可外推。两者都必须有。见第 4 节陷阱 5。

## 4. 六项会导致错误结论的实现陷阱

评估代码里有六处写法会直接产生错误结论。它们都不是会报错的 bug——每一段代码都能正常运行并输出一个看起来合理的数字——这正是危险之处：把噪声读成信号，且不留下任何异常痕迹。本节逐条列出症状、后果与替代做法。**请勿跳过。**

### 陷阱 1：滚动评估必须按时间分组，不能按行号切片

**错误做法**

```python
def rolling_evaluation(y_true, y_pred, window=3):
    records = []
    for i in range(0, len(y_true) - window):
        yt = y_true[i:i+window]
        yp = y_pred[i:i+window]
```

调用时传入 `window=200`，并按**数组行号**切片。

**为什么错**：面板数据的一行是一个 `(ticker, date)`，行号与时间没有对应关系。同一日期的多家公司在数组中相邻，因此一个 200 行的窗口可能只覆盖 1–3 个交易日，也可能横跨数月——取决于每个日期的公司数量与排序。更严重的是，如果数据先按公司排序（很常见），那么一个窗口内的全部样本来自同一家公司，AUC 会退化成对单家公司时序的判别，与"滚动评估稳定性"的目的完全无关。

**替代做法**：按时间单位分组，而不是按行号：

```python
for period, idx in df.groupby(df["as_of"].dt.year).groups.items():
    metrics = evaluate_classification(df.loc[idx, "y_true"], df.loc[idx, "y_pred"])
```

`eval/splits.py` 的 `rolling_windows()` 直接产出 `(period_label, index)` 对，`eval/stability.py` 消费它。每个窗口内必须同时有正负样本，否则该窗口记 `insufficient_positives` 并在报告中标注，而不是静默产生一个 NaN 或 0.5 的 AUC。

**一个附带的细节**：`range(0, len - window)` 配 `window=200` 这种写法会在 1000 行上产生 800 个窗口，彼此重叠 199 行，输出一张高度自相关的表。按时间分组天然消除了这个问题（每个时间单位只出现一次）。

### 陷阱 2：分位回测必须逐日横截面排序，不能对全样本池化取分位

**错误做法**

```python
df["quantile"] = pd.qcut(df["pred"], n_quantiles, labels=False)
result = df.groupby("quantile")["ret"].mean()
```

**为什么错**：两点。

1. **池化取分位混淆了时序与横截面**。`qcut` 在整个样本池上取分位，因此一个 2008 年的样本是否落在第 5 分位，取决于它与 2021 年样本的相对分数。但模型分数会随市场 regime 整体漂移（高波动期所有公司的风险分都抬升），于是"第 5 分位"在不同时期对应完全不同的公司集合——早期可能整组都是正常公司，崩盘期可能整组都是高风险公司。分位组的含义因此不稳定。
2. **单期支配**。池化均值对样本数多的时期赋予更大权重。新闻与披露密度、公司数量随年份变化，因此某一期（通常是近年）会支配结果。

**替代做法**：**逐日（或逐调仓周期）做横截面排序**，再对每个分位求时间序列均值：

```python
df["quantile"] = df.groupby("as_of")["pred"].transform(
    lambda s: pd.qcut(s.rank(method="first"), n_quantiles, labels=False)
)
per_date = df.groupby(["as_of", "quantile"])["ret"].mean().unstack()
mean_by_quantile = per_date.mean(axis=0)     # 每个分位的时间序列均值
long_short = per_date[n-1] - per_date[0]      # 多空价差的时间序列
```

关键点：`long_short` 现在是一条**时间序列**，可以据以计算 Sharpe、最大回撤、以及 Newey-West 调整后的 t 统计量。这才是"经济意义"的证据；池化均值无法支持任何显著性检验。

### 陷阱 3：IC 必须用连续的前瞻量

**错误做法**

```python
def full_evaluation(y_true, y_pred, future_return=None):
    print("排序指标:", evaluate_ranking(y_pred, y_true))   # y_true 是 0/1 标签
```

即用二值的 `y_true` 作为"未来真实风险"去和预测分数求 Spearman 相关。

**为什么错**：

1. **信息量坍缩**。0/1 变量只有两个取值，与它的秩相关系数主要由"正样本是否排在负样本前面"决定，与 AUC 高度重复。它丢掉了"风险有多严重"这一维——两个都未违约的样本，一个平静，一个经历了 -28% 的回撤，在这个 IC 里完全等价。
2. **与真实用途不符**。分数是用来做风险排序与仓位调整的，需要与**风险的连续幅度**相关，而不是与一个年度二值事件相关。
3. **有偏**。Spearman 在大量并列值（这里是 95% 以上的 0）下，系数会被并列处理方式影响，可比性差。

**替代做法**：IC 使用连续的、前瞻的、且与标签不同源的风险幅度。本项目提供两个：

| 前瞻量 | 定义 | 适用 |
| --- | --- | --- |
| `fwd_realized_vol_21d` | 未来 21 个交易日的已实现波动率（年化） | **默认**。对三个标签都适用，样本量充分，噪声低于收益 |
| `fwd_max_drawdown_30d` | 未来 30 个交易日的最大回撤（负值） | `tail_risk` 的连续对应量 |
| `fwd_ret_21d` | 未来 21 个交易日收益 | 仅作辅助参考。收益的噪声远高于波动率，IC 波动会很大 |

计算方式也必须在横截面上做，理由和陷阱 2 相同：逐日计算横截面 Spearman，得到 IC 序列，再取均值（即 IC）与 IC/σ(IC)（即 ICIR）。直接对池化样本求一次 Spearman，同样受 regime 漂移影响。

相关约束：`fwd_*` 列是**评估目标**，不是标签（见[标注](03-labeling.md)第 1.3 节）。它们与 `label_*`、`event_*` 一样命中 `leakage.py` 的列名黑名单，绝不进入特征矩阵。

### 陷阱 4：切分必须 purge + embargo

**错误做法**：完全没有切分逻辑，`full_evaluation` 在整份数据上直接算指标；切分只在文字里给出"训练 2001–2018 / 验证 2019–2020 / 测试 2021–2025"这样的名义边界，代码并不执行它。

**后果**：在 365 天（`fraud_risk` 为 730 天）的标签 horizon 下，训练集末尾与验证集、测试集之间存在大面积标签窗口重叠。测试指标会被系统性高估，且高估幅度随 horizon 增长。这类泄漏不会报错，只是让数字好看——正是最难被发现的错误类型。

**替代做法**：`eval/splits.py` 实现 purged walk-forward with embargo，参数与公式见第 3.2 节，算式见第 3.3 节。三条硬规则：

1. 任何折的训练样本，其信息占用区间 `[as_of, as_of + H]` 不得与后续折区间相交。
2. 边界处额外丢弃 `embargo_days`（默认 30 交易日）的样本。
3. 测试折的右端按 `data_end - H` 截断，未走完标签窗口的行标记 `label_mask = false` 并从评估中排除。

报告必须打印每折的实际有效区间（不是名义区间）。没有有效区间记录的报告视为无效。

### 陷阱 5：静态切分不够，必须有 walk-forward

**错误做法**：只呈现一个静态 train/valid/test 划分，视为充分。

**为什么不够**：单一测试区间只是一个 regime 样本。若测试区间恰好是低波动期，模型显得稳定；若恰好包含一次系统性冲击，模型显得失效。两种结论都无法外推。

**替代做法**：两条都要。

- 静态切分 → headline 数字，只跑一次。
- walk-forward（expanding window，`test_block_years=2`）→ 稳定性证据，全部折报告，含置信区间与趋势判断。

同时在报告中明确：headline 数字来自哪个测试区间，该区间的市场 regime 特征是什么（用 VIX 均值、指数最大回撤等指标描述）。脱离 regime 描述的单一数字不应被引用。

### 陷阱 6：显式校准，不用已废弃的 `prefit` 接口

**错误做法**：没有校准步骤（`expected_calibration_error` 只是**测量** ECE，不产生校准后的概率），模型输出的 `y_pred` 被直接当作概率使用；也没有说明校准器应当在哪个区间拟合。

**问题**：未经校准的树模型或 LLM 分数不是概率。用它算 ECE 只是测量了"未校准"这一事实，不构成校准。另外，scikit-learn 的 `CalibratedClassifierCV(cv="prefit")` 一类接口已废弃，且其语义容易让人把校准数据与评估数据混用。

**替代做法**：

1. **Track A**：在 train 上拟合 GBDT → 在 **valid** 上拟合 isotonic（valid 正样本 >= 50）或 Platt → 冻结 → 在 test 上 transform。详见[训练](04-training.md)第 1.3 节。
2. **Track B**：LLM 输出的 `score` 同样不是校准概率。做法是把 `score` 视为一个连续的特征，在 valid 上拟合一个形如 `Platt(score)` 的一元校准映射，再进入融合层与评估。**不**把 LLM 的自我报告概率当概率。
3. **融合层**：logistic stacker 或 rank-average 的权重同样只在 **valid** 上拟合。test 上只做一次前向计算。
4. **评估集不降采样**。校准只有在真实基率下才有意义；训练时降采样后必须用 `sample_weight` 把概率对齐回真实基率（见[标注](03-labeling.md)第 5.2 节）。

报告的必填元数据：校准器类型、拟合区间、样本数、正样本数。缺任一项的报告视为无效结果。

## 5. 基线、消融与三路对比

### 5.1 必须报告的路径

| 路径 | 输入 | 目的 |
| --- | --- | --- |
| `random` | 无 | 理论下界：AUC=0.5；PR-AUC=正样本率 |
| `buy_and_hold` | 无 | 回测基准：S&P 500 买入持有 |
| `equal_weight` | 无 | 回测基准：等权组合 |
| `structured_only` | 财务比率 + 技术 + 文本计数量 | Track A 单独表现；**融合判据的对照** |
| `structured_matched` | **只**用 prompt 里那 12 个结构化信号 | **同信息量基线**：`text_only_* - structured_matched` 才是文本增量 |
| `text_only_tfidf` | 文本（词袋/TF-IDF） | 文本是否有用，与 LLM 无关 |
| `text_only_zero_shot` | 文本 + 基础模型零样本 prompt | 微调带来的增量 |
| `text_only_lora` | 文本 + QLoRA 微调 | Track B 单独表现 |
| `fused_stacker` | Track A + Track B 分数 | **主结果** |
| `fused_rank_avg` | Track A + Track B 分数 | 对融合方式是否敏感的对照 |

**为什么必须有 `structured_matched`，而不是拿 `structured_only` 相减。** 文本轨的 prompt 里带 `<STRUCTURED_SIGNALS>` 块，含 `PROMPT_SIGNAL_COLUMNS` 那 12 个信号（见 4 节陷阱与 02-data）。也就是说 `text_only_lora` 的输入**不是纯文本**，而 `structured_only` 用的是全特征集。两者相减同时混入"模型不同"与"信息集不同"两个因素，结果看起来像一个答案，其实不是。把同一个估计器限制在那 12 列、用同一 train/valid/test 与同一校准折再拟合一次，减法才只表示"文本带来了什么"。

这条基线已经进入标准报告：`shingan eval run` 的对比表自 2026-09-23 起有 **4 行**（`structured`、`structured_matched`、`text_baseline`、`fused`），此前的报告只有 3 行。它的拟合与打印顺序由 `pipeline.COMPARISON_ORDER` 决定，而 `PATH_ORDER` 仍是三条**轨道**——控制项不进 `PATH_ORDER`，否则它会经 `score_*` 列渗进漂移、滚动稳定性、压力测试与消融表。

**`text_only_zero_shot` 与 `text_only_lora` 必须同一次跑出来。** 它们的价值是**差值**（微调买到了什么），而跨两次命令的两个数字不是一次配对测量。`shingan eval lora --mode both` 用同一份 base 权重、同一个 tokenizer、同一组 prompt 依次生成两臂，并把 `lora - zero_shot` 作为一条配对区间报出；`--mode zero_shot` 则只出零样本臂。两者都用 `structured_matched` 作为同信息量基线。

**这一行的状态（2026-09-23，同日两次）**：命令已存在；第一次跑出来时**不可引用**——零样本臂 64 行里只有 4 行通过 schema 校验（失败率 0.9375），且这 4 行全是负样本，9 个正样本全被丢弃，AUC / PR-AUC 无从计算。失败原因是**指令契约缺口**而非模型能力：`SYSTEM_PROMPT` 点了 `source_type` 的名，**却没有枚举它的合法取值**，模型只能去猜块名。

缺口当天即修（补枚举 + 补 `source_ref` 的形状）、语料重生成、适配器重训，再跑一次：**两臂都 64/64 解析成功**，零样本 **AUC 0.5172 / KS 0.1273 / 方向 `positives_higher`**（表里唯一方向正确的一行），适配器仍是 **AUC 恰 0.5000 / KS 恰 0.0000** 的常量。于是 `lora − zero_shot` **第一次可测**：AUC −0.0172 [−0.2890, +0.0628]、PR-AUC −0.0169 [−0.1033, +0.0066]，**区间跨零**。可写的结论是“微调没有可测量的正增量，且把一个非退化排序变成了常量”；不可写“显著变差”。详见 [09 LoRA 评测](09-lora-evaluation.md) 第 12、13 节。

这张表直接对应 `shingan eval compare --runs structured text fused`。

### 5.2 消融

| 消融 | 做法 | 要回答的问题 |
| --- | --- | --- |
| 去掉文本 | 只留结构化 | 文本的整体增量（等于 `structured_only`） |
| 去掉财报文本 | 只留新闻 | 新闻与财报各自的贡献 |
| 去掉新闻 | 只留财报 | 同上 |
| 去掉技术指标 | 只留财务比率 + 文本 | 量价信息的作用 |
| 去掉财务比率 | 只留技术 + 文本 | 财报数值的作用 |
| **打乱文本（placebo）** | 把文本随机置换到其他公司/时期，保持长度与格式 | **必做**。若指标不下降，说明模型在利用长度、公司身份或标签泄漏，而不是文本内容 |
| 打乱文本顺序 | 保持样本不变，打乱段落顺序 | 模型是否依赖特定段落位置 |
| 去掉结构化信号摘要 | prompt 中不提供 `<STRUCTURED_SIGNALS>` | 文本轨是否在"复述"结构化信号（这会削弱融合的意义） |

**placebo 对照是本文档强调的第二个硬要求**（第一个是三路对比）。稀有事件 + 小样本 + 高维文本的组合极易产生伪信号，打乱文本后指标不下降的情形并不罕见。没有 placebo 对照的正面结果不予采信。

### 5.3 一个必须提前说明的限度

`fraud_risk` 的 730 天 horizon 加上第 3.4 节的窗口截断，意味着它的 test 有效区间只有 2 年、valid 有效区间约 22 个月，且尾部 13 个月被 purge 吃掉。在这个规模下，`fraud_risk` 的 AUC 置信区间会非常宽。**因此本项目的 headline 判据放在 `default_risk` 上，`fraud_risk` 作为探索性结果报告并附置信区间**，不设硬门槛。把 `fraud_risk` 的漂亮数字当作主要结论是过度解读。

## 6. 压力测试

| 场景 | 区间 | 检验什么 | 数据可用性 |
| --- | --- | --- | --- |
| 2008 金融危机 | 2008-09 .. 2009-06 | 系统性信用冲击下的区分力与校准 | 需要数据回溯到 2005 年之前。Stage 2 的 2015–2024 跨度**无法支持**，只能在 Stage 4 之后做 |
| 2020 疫情崩盘 | 2020-02 .. 2020-06 | 单季极端波动下的分数稳定性 | Stage 2 可用 |
| 2022 加息周期 | 2022-01 .. 2022-12 | 久期/利率敏感型风险的识别 | Stage 2 可用 |
| 流动性枯竭（合成） | 用历史重采样构造 | 极端场景下排序是否仍然合理 | 属于构造场景，必须明确标注为合成压力场景 |
| 利率冲击（合成） | 用宏观因子扰动 | 高杠杆实体的相对排序是否恶化 | 同上 |

三条规则：

1. **压力区间必须在训练区间之外**，否则测的是记忆而不是泛化。若某压力区间的数据被用于训练，该压力测试结果无效，报告必须标注。
2. **每个压力场景报告完整的指标向量**（AUC/KS/PR-AUC/IC/ECE/分位收益），不是一个汇总分数。极端区间的正样本数很少，单一数字的噪声极大。
3. **合成压力场景不得与历史场景混在同一张表里**。前者是鲁棒性探测，后者是实证证据，分开呈现。

`eval/stability.py` 提供 `stress_window(df, start, end)` 与 `synthetic_stress(df, kind)` 两个入口。

## 7. 漂移监控

| 监控对象 | 指标 | 阈值 | 处置 |
| --- | --- | --- | --- |
| 输入特征分布 | PSI（按特征，逐期对比基准期） | < 0.25 | 超过即标记该特征为不稳定，触发重训评估 |
| 模型分数分布 | CSI | < 0.25 | 超过即警告，检查是否有 regime 切换 |
| 正样本率 | 逐期实际正样本率 | 与训练期基率对比 | 基率漂移会直接破坏校准，必须重拟合校准器 |
| 校准 | 逐期 ECE | < 0.05 | 超过即触发校准器重拟合（不需要重训模型） |
| 特征缺失率 | 逐列缺失比例 | 与训练期对比 | 突增通常意味着上游数据源变化，而非模型问题 |

实现：`eval/stability.py`。基准期固定为 valid 区间，逐期与基准期对比，**不滚动更新基准期**（滚动更新会让漂移被慢慢吸收掉，直到某天突然爆掉）。

## 8. 可解释性

可解释性在本项目中不是附加功能，而是输出契约的一部分（见[架构](01-architecture.md)第 7 节）。

| 层次 | 方法 | 产出 |
| --- | --- | --- |
| 结构化轨 | 特征重要性 + 单样本归因（SHAP 风格，或 LightGBM 的 `pred_contrib`） | `signal_attribution.structured_top` |
| 文本轨（注意力） | attention 分布，定位模型关注的段落 | 段落级热力图；仅作诊断，不作为证据 |
| 文本轨（引用） | 输出中的 `evidence[].quote` + 逐字子串校验 | 可核对的证据列表 |
| 融合层 | stacker 的系数（logistic 情形）或权重（rank-average 情形） | `fusion_weight_text`，直接读出文本轨的贡献 |
| 案例研究 | 挑选最高/最低分各 5 个样本人工复核 | 写入报告的 case study 段落 |

两条纪律：

1. **注意力不是证据**。注意力权重与因果贡献之间的对应关系在文献中被反复质疑。模型"关注"了某一段，不等于这一段驱动了分数。报告中的 `evidence[]` 必须来自输出文本的显式引用并通过子串校验，注意力图只放在诊断附录。
2. **归因方向必须符合金融逻辑**。`interest_coverage` 上升应当降低 `default_risk` 分数；`negative_kw_density` 上升应当提高它。方向不符时优先怀疑实现（特征符号错误、join 错位），而不是"模型发现了新规律"。

## 9. POC 验收门槛

以下为**目标值**，不是达成值。任何一项未达成，都必须如实报告为未达成。

| 门槛 | 判据 | 备注 |
| --- | --- | --- |
| Headline 区分力 | **AUC > 0.75** 且 **KS > 0.3**，在静态切分的 test 上 | 针对 `default_risk` |
| 融合增益 | **fused 的 PR-AUC 显著高于 structured_only** | 项目核心论点。需附 bootstrap 置信区间，且区间不跨零 |
| 文本增量（对照） | fused 高于 text_only_lora，且 text_only_lora 高于随机 | 两条轨各有贡献 |
| Placebo | 打乱文本后指标显著下降 | 排除捷径 |
| 校准 | **ECE < 0.05**，且 Brier 优于常数基率基线 | 在未降采样的 test 上 |
| 稳定性 | walk-forward 各折指标的 bootstrap 区间稳定地高于随机，无单调下降趋势 | 不用"波动 < 10%"这一不可达门槛 |
| 经济意义 | 横截面分位收益单调，多空价差 t 统计量（Newey-West）显著 | Sharpe > 1.0 作为目标，不作为门槛 |
| 差异显著性 | 关键比较的置信区间不跨零 | 小样本下必须报告区间，禁止只报点估计 |

关于"显著"的判定：本项目的样本量不大、正样本少，因此所有关键比较都用 **bootstrap（按时间块重采样）** 给出置信区间，块长不小于标签 horizon，以避免块内自相关被低估。禁止使用基于 i.i.d. 假设的 p 值。

## 10. 什么会证伪这个项目

这是本文档中最重要的一节。项目的核心论点是"文本轨在结构化信号之外提供可度量的增量"。以下任一情形成立，即构成对该论点的证伪，应当如实记录并停止扩张：

| # | 证伪条件 | 意味着什么 |
| --- | --- | --- |
| F1 | fused 的 PR-AUC 与 structured_only 的置信区间大幅重叠，无显著差异 | 文本轨无增量。项目的中心论点不成立，双轨架构退化为一个更贵的单轨 |
| F2 | 打乱文本后指标没有显著下降 | 模型没有在使用文本内容。它可能在利用长度、公司身份、或某个未被发现的数据泄漏。此时所有正面结果都无效 |
| F3 | `text_only_tfidf` 追平 `text_only_lora` | LLM 相对词袋没有增量。应把资源转向特征工程或数据质量，而不是更大的模型 |
| F4 | IC 的置信区间跨零 | 分数没有横截面排序能力。即使 AUC 高，也说明区分力来自少数极端样本，不可用于排序 |
| F5 | 未校准的 ECE 与校准后的 ECE 差异微小，且两者都 > 0.05 | 分数无法作为概率使用，不能进入任何需要概率的风险流程 |
| F6 | 在加入市场 regime 变量（VIX、指数回撤）后，模型增量消失 | 模型的"风险预测"实际是市场 beta 的代理，没有公司特异信息 |
| F7 | walk-forward 中后期折的性能系统性低于早期折 | 模型在学习随时代变化的模式（例如会计政策、披露格式、市场结构），而非稳定的风险机制 |
| F8 | 全部指标优于基线，但正样本的绝对数量小于 20 | 统计上不可判定。应报告为"证据不足"，而不是"通过验收" |

F8 值得单独强调：**在正样本只有个位数的情况下，任何 AUC 都可以被一两个样本的排序改变**。这不是模型的成绩，也不是模型的失败，是样本量不足。把它报告成结果是不诚实的。

同时列出本项目**不打算证伪但已知会失效**的边界（来自[架构](01-architecture.md)的非目标）：

- 无历史先例的黑天鹅事件（无训练分布）。
- 内部操作风险（未披露则不在数据中）。
- 主权/政治风险（超出 US-listed 覆盖）。
- 流动性黑洞（历史价量关系失效）。
